# Run the example; do not shop for a picture of it

All film builders must distinguish an irreplaceable source artifact from a
visual we can compute. Pantry is appropriate for the actual historical photo,
document, external recording or other source evidence the claim depends on.
It is not a default route for code, arithmetic, tables, charts or toy examples.

Before any pantry request, ask whether local code/data can establish the point.
If yes, run it, preserve the exact code, environment, seed, stdout/stderr and
input/data hashes, then render the result clearly with a suitable component.
Real Python output may be typeset in a readable terminal-style teaching view;
label it as recorded output/reconstruction, not a live screen recording.
Do not fabricate success, error messages, measurements or historical UI.

Generated screenshots, stock pictures of terminals, notebook photographs and
index-card photographs add no evidence to locally reproducible examples. Prefer
the executed computation and animated data. A hypothetical answer key or other
constructed illustration must be labeled as constructed, not an empirical test.

If execution is unavailable or unsafe, state that limit and use clearly labeled
pseudocode or an illustration only when that still teaches honestly. Do not
pretend an image generator executed the program. Preserve necessary pantry
requests, but do not impose a media quota or ask the human to take a screenshot
of work the agent can safely run. No paid generation is implied.
