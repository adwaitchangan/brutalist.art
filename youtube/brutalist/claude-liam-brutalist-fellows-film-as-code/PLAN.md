# Fellows: Film as Code, Work as Evidence

Playlist slot: 5, immediately after “The ai-explainer Skill.”  
Format: deep-explainer, Claude/Liam bookends, approximately 5–7 minutes.  
Primary source: `humanitarians-youtube/fellows/` after the September 8 sync and cleanup.

## One claim

A fellow’s finished video is the visible result, but the repository is the
evidence: its beat sheet, sources, code, checks, and review trail show what was
claimed, how it was built, and whether another person can reproduce it.

## Act map

### Bookends — Ask and corrected overview (2 beats)

- B00 asks where the work behind a finished fellow video actually lives.
- B01 corrects “the MP4 is the project” to “the MP4 is the output; the repo is
  the record.”

### Act I — The golden rule (5 beats)

- Rebuild Sanjanna’s rule as a clean decision: GitHub for text and source;
  Drive for rendered video and large media.
- Work the edge case: a large text file still follows the size limit.
- Show the fellows directory after normalization: portable lowercase-kebab
  paths, no MP3 or MP4 files.
- Explain why Drive links belong in the project README.
- Falsifiability: if the repo cannot rebuild or explain the film, “film as
  code” is only a slogan.

### Act II — One contract, many films (7 beats)

- Show the shared `metadata` + `beats` contract.
- Compare a 4-beat brief, the 10-beat median project, and a 32-beat deep
  explainer side by side.
- Compare landscape/vertical conventions: sibling short sheet, nested
  `short/beat-sheet.json`, and named short variants.
- Show the medium range: Remotion structure, fellow-owned evidence, Manim,
  stills, and archives.
- Explain that variation is allowed because the contract coordinates work; it
  does not flatten every story into one template.
- Worked example: trace one claim from narration to visual instruction to
  source/check artifact.
- Boundary: a beat sheet is not proof by itself; unsupported narration remains
  unsupported.

### Act III — The repository as evidence (7 beats)

- Claim → source → beat → render instruction → check → review decision.
- Project updates foreground owned screenshots, measurements, and results.
- Technical explainers expose code and simulations.
- Research explainers expose citations, uncertainty, and corrections.
- Build logs preserve decisions that disappear from a final cut.
- Review files make “approved” inspectable rather than ceremonial.
- Reproduction test: a new maintainer should be able to understand what exists,
  what is missing, and how to rebuild without asking the original author.

### Act IV — The weekly pipeline (5 beats)

- Two topics, two native aspects: four deliverables, but one source record per
  project.
- Fellow scope: create, document, upload media to Drive, link it from GitHub.
- Reviewer scope: format, 4K, legibility, intro, and actual viewer takeaway.
- Maintainer scope: merge source, queue approved media, preserve the audit trail.
- The repository and Drive complement each other; neither substitutes for the
  other.

### Closing block (3 beats)

- Verdict: the film earns attention; the repository earns trust.
- Your Turn: choose one existing fellow project and make its claim-to-evidence
  chain reconstructable.
- Title restate: “Fellows: Film as Code, Work as Evidence.”
