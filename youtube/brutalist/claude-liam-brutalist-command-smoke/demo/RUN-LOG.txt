==== SECTION 1 — dispatcher case (art:114-116) ====
  smoke)
    exec bash "$ART_HOME/runtime/scripts/smoke_test.sh" "$@"
    ;;

The wrapper resolves ART_HOME from art's own path, execs smoke_test.sh with
no arguments (no flags exist), and forwards $@. Contrast with `art doctor`,
which forwards to the setup script's readiness check — smoke instead builds
the tiny examples/_smoke/ fixture end to end and verifies the decoded mp4.

Diagnosis: examples/_smoke/beat_sheet.json ships with metadata.slug = "_smoke".
build_safety.validate_project() requires slug =~ /^[A-Za-z0-9][A-Za-z0-9._-]*$/
(build_safety.py:186-187), which rejects the leading underscore. The failure
is not in the audio engine; it is in a static validator that runs BEFORE
Kokoro is loaded. `./art doctor` on the same box still reports every FEATURE
green — because doctor checks dependencies in isolation, not the pipeline —
which is exactly the gap `./art smoke` exists to close.

==== SECTION 4 — the coupling smoke_test.sh assumes ====
smoke_test.sh:60 hardcodes:  OUT="$WORK/_smoke-slate.mp4"
compile.py names the output after the beat sheet's slug (<slug>-slate.mp4),
so smoke_test.sh silently requires the fixture slug to be exactly "_smoke".
The recent build_safety slug regex rejects that same value. Two shipped
files disagree; smoke exists to make that disagreement visible.
