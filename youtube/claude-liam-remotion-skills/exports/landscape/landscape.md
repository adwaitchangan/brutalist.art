## claude-liam-remotion-skills

Hey Claude, I just installed Remotions own agent skills into the Brutalist Toolkit. What do they actually do? And what do they let the toolkit do that it couldn't before? Saoabona, this is Liam in for Bear, first a correction. These skills are not a plugin that renders anything. They are 50 short rule files that load into an agent mine included when it writes Remotion code so the code it writes is the current correct way. Frame-driven motion, timing on the node, permitted media, measured text, captions as data. This film shows each rule running for real in the Brutalist Toolkit. And then the three things that needed a newer Emotion, now rendered live. What a skill is, one command inside the Remotion project installs them, seven folders under dot agent slash skills, and a simlink from dot clawed slash skills so Claude code finds them. A lock file records the exact version so an update never changes the rules halfway through a film. Open one, a skill is a markdown file with a name, a version, and rules. The markup skill opens with the two that matter most. Take the frame rate from the video config and keep timing on the JSX node and drive every animation from the current frame. A CSS transition will not render. The router skill sends an agent to the right file for the task. The first rule shown two boxes are told to slide across the stage. The left one uses a CSS transition. The right one uses interpolate over the current frame. Remotion renders one frame at a time as a screenshot so a CSS transition never gets its two seconds. The left box teleport to the end in a single frame and sits there. The right box moves and lands in the same place in every render. That is the whole reason for the rule. Easing four dots travel the same distance in the same time. Linear is mechanical. The bezier the skills recommend .161.31 arrives fast and settles. A spring with heavy damping pushes with no bounce. In the last pair show scale, the same growth looks slow at the end unless you ask for perceptual scale which the skills now call out. Easing a series lays clips end to end and the skills say. Promount every timed item one second early with promote for equal to the frame rate so media and fonts are ready before the cut. Watch the ruler. The gray band before each clip is the promote. The playhead crosses it and the clip is already there when its turn comes. Transitions. The transition's package gives a transition series with fade, slide and white between scenes and the skills explain the trap. A transition overlaps its neighbors so the composition is shorter than the some of its scenes and you subtract the overlap when you compute the length. Three cards, three cuts and the running frame count shows the overlap. Measuring text, the layout utilities measure a string in its real font before it is placed. The left box sets a long title at one size and clips it. The right box asks fit text for the largest size that fits the width and shows the size it found. For this toolkit that is the difference between catching a truncated title in a gate and never producing one. Captions as data, the captions package parses a subtitle file into caption objects with start and end times in milliseconds. This is a real caption file from the first film in the Northeastern Research Computing series and these are its first cues drawn as pages each word lighting on its own time. The toolkit already writes these files, now a composition can read them. Audio visualization, the media utilities read the waveform of an audio file and give a spectrum per frame. These bars are this sentence, my own narration, analyzed as it plays nothing faked. This on the left, treble on the right and the shape follows the voice. Media, the multimedia skill reads a file's duration with the Media Bunny Library instead of shelling out to FF Probe. Here it measures the opening card of that same research computing film, 12.528 seconds where FF Probe says 12.48, the gap being how each counts the last MP3 frame. The toolkit's clock stays in Python but a composition can now size itself from the audio it plays. Render, the render skill is the command line, render, still in a frames mode that writes several frames as images in one call, which is exactly how this toolkit's gate sample would be. It also documents transparent output, PNG frames and alpha pixel format, pro-res 4444 or VP9 for a clip that drops onto another video with no background. And the toolkit already renders every card this way. The writing quill from the previous film rendered as a still with alpha sits on a craft checker board with nothing behind it. That is the same render path with the flags the skill names. Now the part that needed the upgrade, three of the rules describe features newer than the remote this toolkit was running. So the toolkit moved from 4.0.486 to the latest 4.0.534 every remote and package at once as the upgrade skill says. React went to 19 with it because the new transitions build carries React 19 inside, then every composition was re-rendered in the effects. Highlights and blur below are real renders, not captures. First effects and effects array on images, video and solids drawn by the graphics card. Here is one portrait of Professor Bear 4 ways, Grace Kale, Duton in the Toolkit's own Inc. craft, a terracotta half-tone and a vignette with roughened edges. Each is one line driven by the frame, and the documentary still treatment the toolkit used to build by hand is now exactly that. Second text highlights, hand drawn circles, highlights, underlines, strike-throughs and boxes, each a component driven by a progress value from the frame. The terracotta ring this toolkit used to draw by hand in every scene is now a circle around a word. Third motion blur, the top card is a hard-edged move, every frame sharp. The bottom is wrapped in camera motion blur, which renders each frame at 12 moments inside a 240-degree shutter and averages them, so the card smears the way a real camera sees it. The newer HTML and canvas blur needs a chrome flag, so this is the component that runs everywhere. Keeping it current, the skills come from a public repository, and one command pulls up updates. The lock file changes with them, so the update is a diff you can read before the next film, and a commit you can roll back. The old snapshot in the toolkit's docks folder now points at the live set. Let's recap with Claude. The skills are rule files and agent reads while it writes remotion code, not a renderer. The rules that matter, frame-driven motion, timing on the node, promote a second early, measure text before placing it. They are installed at a pinned version with transitions, layout utilities, captions and media utilities added to match. As an audio-become data, a composition can read while the toolkit's clock stays in Python. The toolkit then upgraded to the latest remotion with React 19 and effects, text highlights and motion blur now render live, and an update is a command and a diff. Turn, paste this into Claude.
